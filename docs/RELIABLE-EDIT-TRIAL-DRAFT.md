# Reliable edits with discoverable typed vocabulary

Status: research draft, not a frozen protocol or an executed result. Finish the
unchanged retention-003 comparison first. No new actors are authorized by this
document alone; existing human authorization governs experiment execution.

## Question

Does discoverable, strongly typed retained vocabulary help a fresh external AI
coding agent make correct changes and catch shared defects without introducing
unrelated regressions? Test both beneficial reuse and defect propagation. A lean
mailbox release runtime is a separate engineering and memory evaluation.

## Smallest useful comparison

Use the signed Int64 Money business domain and existing independent BigInteger
oracle. Candidate task: implement an exact discounted-balance extension and
correct affected established behavior for all signed balances. A hidden seeded
negative-balance clamp must be exercised by the public task, not an irrelevant
trap. Freeze exact public names, fixtures and behavior before launching.

Compare clean rich language vocabulary with an otherwise identical defect-seeded
copy, and clean conventional F# helpers with their equivalent mutant. Include a
schema-only Flat condition as an exploratory reference; its different API surface
precludes treating its result as an isolated retention effect. Start with five
fresh actors as feasibility only; repeating each condition with rotated order
would yield ten observations, still insufficient for general superiority claims.

## Independent outcomes and controls

- Verify exact raw ordinal premium classification and truncation toward zero
  using BigInteger, including negatives, Int64 endpoints and values beyond Float
  precision. Verify both the extension and affected existing callers.
- Verify unrelated behavior, definitions, nominal identities and persisted state.
  Define permissible intentional test corrections before launch; do not require
  preserving a deliberately incorrect expected value.
- Score independently correct completion, propagated defect, unrelated regression
  and unresolved task separately. Test or coverage success alone is insufficient.
- Record explicit discovery and repair evidence; do not infer an internal insight
  from a passing final implementation. Distinguish workaround from shared repair.
- Preflight known-good code and clamp, Float-rounding and wrong-case mutants.
  Wrong implementations must fail independent acceptance even if own tests pass.
- Separately test valid edit acceptance and rejection of nominal-type mismatch
  and undeclared effects before execution or persistent mutation. False rejection
  of valid code is friction, not successful issue detection.

Preserve failed outputs without coordinator repair and report every condition.
Protocol calls and bytes are available. Authoritative model tokens, turns,
effective context windows and controlled task latency are unavailable through
the present native-subagent interface; do not substitute protocol measurements.

## Existing evidence

Reports 068 and 069 show one successful shared-defect repair and one behavior-
preserving refactor. Report 076 shows exact-Money trials and the insufficiency
of own coverage. Reports 064 and 079 establish bounded discovery/reuse feasibility
with their reported limitations. None establishes a controlled reliability
advantage. Reuse fixtures where semantics and provenance match; revalidate and
freeze a new oracle and design rather than changing any completed study.
