# Frontend and source-library revision plan

**Status: implementation pending.** This plan links the approved language direction in [docs/PRD.md](../docs/PRD.md). It is based on the current `prototype` checkout and preserves the requirements added during this conversation.

## Current repository evidence

- The current expression frontend is Flow/1. Its AST is authoring-only and retains source text, spans, and syntax versions (`src/AgentLang.Core/FlowSyntax.fs:5-7,65-111,142-151`). `FlowParser.parseExpressionState` recognizes calls and dot calls; every dot stage currently requires parentheses (`FlowParser.fs:549-607`). The word parser accepts `word`, stores effects as a set, and rejects a missing `effects` line (`FlowParser.fs:648-718`). The AST therefore cannot currently distinguish omitted effects from explicit `effects none`.
- Flow lowering rejects versions other than 1 and carries `SourceText` and `SyntaxVersion` into lowered definitions (`FlowLowering.fs:1573-1605`). Source-backed definitions are checked against exact retained source bytes and their lowered signature, documentation, effects, and body (`FlowLowering.fs:1709-1726`). Runtime registration and reload also currently accept only Flow/1 (`Runtime.fs:2915-2916,3002-3003,3159-3160`). Storage persists a `SourceFormat` on revisions, but rejects syntax versions other than 1 (`Storage.fs:367-380,605-632`). Keep these Flow syntax versions distinct from the storage manifest version.
- A canonical Flow renderer exists (`FlowSyntax.fs:492-509,627-642`), but it renders ASTs as `word`, always prints an effects line, and places `doc` directly before body code. It does not preserve comments or authored layout. It is a source renderer, not an explicit source-formatting operation. The AST's original source and spans provide provenance; formatting should return a changed source document and only become retained source after an explicit edit/revision is accepted.
- The existing typed compiler has a generic `equals : a a -> Bool` signature (`Compiler.fs:71-73,117-119`), while record reads already lower to `GetRecordField` after checking the declared record layout (`Compiler.fs:1128-1137`, `TypedIR.fs:649-657`). New `==` and plain record property syntax can therefore target existing typed operations and IR; they need no runtime operation or implicit conversion.
- Maturity is currently runtime state (`WordMaturity` in `Core.fs:85`, persisted on `WordRevision` in `Storage.fs:72-85`). `Runtime.commitCandidates` promotes selected candidates to library maturity when commit requests it, runs their attached tests, then gates library publication on own instruction, branch/case, and iteration coverage (`Runtime.fs:2471-2487,2639-2661,2682-2726`). Tests and examples, maturity, source format, stable IDs, and Flow call bindings are persisted with revisions (`Storage.fs:72-85,605-632`). Flow source declarations have no library-intent field today (`FlowSyntax.fs:102-111`).
- Executed coverage currently records authored instruction sites and branch outcomes for the target word (`Runtime.fs:1344-1377,1394-1399,1885-1894`); `IrCoverageObligations` contains sites and branch outcomes (`TypedIR.fs:176-196`). The library gate has no per-parameter input-value or function-return-value observations. It can miss both inputs to a branchless `Bool -> Bool` identity and `true`/`false` outputs from a branchless function. Current `LangType` supports `Bool`, records, `Option`, and `Result`, but no enum declaration. The effect host is a closed runtime interpreter callback over built-in commands (`Runtime.fs:1378-1405`), not an injectable deterministic provider interface for tests.

## Approved acceptance criteria

1. **Versioned source and calls.** Preserve existing Stack/1 and Flow/1 parse, execution, formatting, and reload behavior. Add a versioned frontend path for `fn` and `library fn`, and persist/reload that syntax version without silently rewriting old source. `fn` remains the ordinary project function form. Module membership must be durable metadata, not inferred from a dotted name or filename. Same-module ordinary functions are callable as private helpers; authored cross-module calls must be qualified and target a published library function. Introspection may show private definitions, while call validation still rejects external access. An ordinary function may be launched only through an explicit host entry point. Built-ins and generated type operations need explicit availability rules in that resolver.

2. **Frontend behavior.** Keep parentheses on ordinary calls and `.method(...)` on ordinary dot calls. Add `record.field` only for a declared field of a plain record and lower it through the existing typed accessor. Add infix `==` with documented precedence and the existing `equals` type and nominal checks; incompatible operands fail before execution. An omitted effects declaration means the empty effect set. Nonempty transitive effects require an explicit declaration and still pass the existing compile-time effect check and runtime capability preflight. Introspection reports the effective empty set when omitted.

3. **Formatting and provenance.** Group function effects before `doc`, then emit exactly one blank line before executable body code. Do not print `effects none` when the contract was omitted. Formatting is an explicit source edit: preserve the input source and frontend version until that edit is accepted, then store the formatted bytes as the new revision source and regenerate spans/call bindings from those bytes. Existing Flow/1 source must continue to round-trip under its old renderer.

4. **Module library policy.** Persist module membership and validate it during compilation and project reload. Same-module `fn` may call private `fn`; cross-module authored calls require qualification and a `library fn` target. `library fn` expresses intent but is not itself qualification: commit must run the strict gate before setting/persisting library maturity. A host entry point may explicitly launch an ordinary `fn`. Keep inspection visibility separate from call visibility. On changes to a library's dependency closure, invalidate its qualification and rerun affected callers' attached tests before publication/use as qualified library vocabulary.

5. **Qualification evidence.** Require 100% own-function branch coverage and the existing own-instruction/case/iteration obligations. Record each target invocation's arguments by parameter and its actual returned value from the tested function's execution. For each finite `Bool` or enum parameter, attached tests must exercise every valid value independently; do not impose a Cartesian product across parameters. For finite declared returns, observe every return value, including `true` and `false` for branchless Bool functions. Cover every enum case when enums exist. For `Option` and `Result`, cover each inhabitable alternative, and enumerate finite payloads; infinite payload domains do not require exhaustive payload values, but alternatives and meaningful boundary tests remain required. Do not waive unreachable values from a broad return contract; use a narrower contract or keep the function at project maturity. Exclude assertion/expectation expressions and unrelated callers from input, return, and branch evidence. Bind successful qualification to the tested revision and dependency identities.

6. **Injected test effects.** Add deterministic effect-provider injection for IO and other declared effects. Injection must preserve the declared effect set, compile-time checking, and runtime capability policy. Tests remain attached to a specific function and coverage is collected only from its actual invocation(s); test expectations run in isolation and cannot contribute coverage.

## Recommended implementation sequence

1. Add the new frontend version and AST metadata for module membership, declaration intent (`fn` versus `library fn`), and omission-aware effects. Extend source-format persistence and reload with backward-compatible Stack/1 and Flow/1 fixtures. Resolve how a source document selects its module and syntax version before coding; the current parser assigns Flow/1 internally and the public frontend selector only distinguishes `stack` and `flow` (`Runtime.fs:2799-2809`). If module membership is stored outside retained source, version the manifest while continuing to load manifest versions 1-3.
2. Parse parameters, calls, property reads, and `==`; lower property reads to declared record accessors and `==` to `equals`. Add a bounded Flow formatter (in `FlowSyntax.fs` or a dedicated formatter module) that follows the explicit metadata layout and operates on a parsed document without replacing retained source implicitly. Preserve `.method(...)` parsing and version 1 fixtures.
3. Add test-only provider injection behind the existing effect preflight. Extend per-test observations with target invocation arguments, return values, and parameter/value identity. Compute finite domains recursively for supported types: Bool and Unit; records whose fields are finite; and Option/Result alternatives with finite payload values. Mark integer, float, string, or composites containing them as infinite; still require each inhabitable Option/Result alternative and boundary tests. Enum-domain support is a future extension because no enum type exists yet.
4. Gate library publication on those observations and existing branch/instruction evidence; persist module membership, maturity, source format, dependency identities, and qualification status atomically. On a dependency change, invalidate dependent library qualification, rerun affected caller tests, and expose the resulting status and compact contract context through introspection. Keep discovery ranking/preferences as a product recommendation, not a prerequisite for this compiler/runtime slice.

## Open design decisions and risks

- The user has approved durable module membership and visibility rules, but the repository does not define whether membership comes from an explicit source declaration, project manifest entry, or both. Choose one stable representation and its migration rules before the source resolver changes. A dotted name alone is not sufficient evidence of module membership.
- Define the exact syntax/version selector for Flow/2 and how source edits that change syntax versions are represented. Persisted source-format metadata exists, but the source parser currently hard-codes version 1.
- Specify which primitive values count as meaningful boundaries for infinite payloads and finite/infinite record fields. Keep that rule deterministic and inspectable; do not convert an unbounded domain into a sampled claim of full coverage.
- Current call bindings preserve target identity, but dependency revision identity and transitive qualification invalidation need to be verified across reload and replacement. Cross-module visibility also needs to apply to compiled and rehydrated call graphs, not only parser name shape.
- Discovery preference and compact contract context remain product recommendations. The approved module rule allows ordinary private helpers in the same module; it supersedes the earlier suggestion that every authored dependency must itself be library-qualified. Qualification still binds that private dependency closure, while cross-module authored callees must be qualified library functions.
