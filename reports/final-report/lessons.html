Lessons and next experiments

The useful output of this experiment is mostly method. A few techniques worked well enough to reuse anywhere. Several choices cost more than they returned. The core question can be tested again, more cheaply, by separating "the workflow" from "a new language".

Techniques worth reusing

1. Oracle-driven porting

Run the original app as a reference. Diff every route's bytes, and run the original's own code (rails runner) as an oracle for computed values. "Done" becomes a diff of zero. It worked for subtle behaviour (ETags, Ruby float printing, signed IDs) and needs no new language. It should transfer directly to agent-driven ports into Go, Rust or TypeScript.

2. Independent grading with calibrated wrong controls

Score agents' work against an oracle they can't see. Prove the oracle fails deliberately wrong implementations. Keep these endpoints separate:

  • behaviour;
  • preservation of existing tests and fixtures;
  • gate passing;
  • session completion.

This exposed that tests plus coverage can certify wrong behaviour, a result that matters for any agent-coding workflow.

3. One verified IR, many backends

An interpreter and a native compiler over one verified IR gave fast tests, fast serving and no semantic drift. If a future project needs a compiled DSL, design it this way from the start.

4. Differential checking of every fast path

The incremental compiler is checked against a from-scratch compile: program, bodies, bindings, and "is any old code still bound?". This made an aggressive optimization safe to ship and caught a real gap in the commit gate. Use the same pattern for caches, incremental builds and optimizers. Make the check mandatory in tests, not opt-in.

5. Two-part builds

Produce a runnable, clearly marked unverified artifact quickly, then run the full verification. Developers and agents get something to try in seconds without weakening the release gate.

6. Capabilities and checked templates

The combination worked:

  • effects in signatures;
  • host-granted capabilities;
  • literal-only SQL;
  • HTML templates with no unsafe holes;
  • OS-only crypto.

Most of it can be approximated in a mainstream language with types, lint rules and template libraries. Test those first.

Things to avoid next time

Building a language to test a workflow hypothesis

The hypothesis was about accumulated, discoverable vocabulary. Testing it with a new language mixed that mechanism with language unfamiliarity and a chatty protocol. Both plausibly worked against the hypothesis, and the small studies could not separate them from the mechanism. The language had to win despite them, and it didn't. Test the mechanism in a language agents already know.

Command-only editing

In the later matched comparisons, agents editing through define, describe and source calls needed about 1.7–5× the broker exchanges of F# agents patching files. Re-submitting whole test sets may also have let collateral test edits slip in. That is a likely contributor, not an isolated cause. Keep files as the editing surface and add structured query tools beside them.

Slow feedback loops

A server build took 5–10+ minutes, and defining one word took 99 s, until the final day. The fixes were not exotic:

  • caching per-batch facts;
  • removing quadratic scans;
  • extending snapshots instead of rebuilding them.

Measure the edit–run loop from day one and treat regressions as bugs.

Treating gates as correctness

Mandatory tests, full coverage and finite-case qualification are useful structure. They are not evidence of intended behaviour. Always keep an independent oracle and a preservation check.

Small samples without a path to a decision

Most comparisons had one or two agents per arm. Each was carefully run, but none could move the conclusion. Decide up front the sample size that would change a decision, and budget for it. Alternatively, choose questions where one run is decisive.

Scope drift without a stop rule

The project moved from research to an application port, to native performance, to build tooling. Each step was justified locally. The original question was not tested again after day 8. Tie each phase to the question it serves, and stop or restate the question explicitly when that link breaks.

Smaller technical lessons

  • Rails' work was the cost. Flow's uncached throughput fell 2.9× (3,488 → 1,221 req/s) once it did everything Rails does to a message body. Benchmarks against a simplified page (report 259) flattered the language.
  • Immutable string concatenation in arenas is expensive at page scale (~650 KB of scratch per ~10 KB message). Plan a builder or rope type early.
  • Interpreter–native parity must cover the builtin set. Builtins that existed only in the interpreter made "tests pass, native build fails" a recurring detour.
  • Per-worker state beats shared state for a dense server. It needs no locks, makes in-place reads simple, and its memory cost was negligible at benchmark scale.
  • Commit gates should follow tests, not just callers. A test attached to an unrelated word can cover changed code. The gate now runs every case whose compiled body reaches the change (PR #7).
  • Discovery details matter to agents. Constructor naming (renewalTiming.new versus RenewalTiming.new) cost real interactions. Generated names should appear wherever the type is described.

Recommended next experiments

These are ranked by expected information per unit of effort.

#ExperimentWhyRough size
1The vocabulary hypothesis in a mainstream language. Use F# or TypeScript. One arm gets mandatory per-function tests, an effect lint and a searchable "vocabulary index" tool (search/describe/source over the repo). The other arm gets the plain repo. Use enough agents per arm (10+) with randomized order.It isolates the mechanism from language unfamiliarity. This is the question AgentLang could not answer cleanly.Days, not weeks
2A preservation guard. A tool that diffs inherited tests and fixtures semantically and blocks unrelated changes unless they are declared.Both AgentLang reliability failures were collateral fixture edits. That problem is independent of language.Small
3Oracle-driven agent porting to a mainstream target (Campfire to Go or TypeScript), using the byte-diff harness.It measures the porting method's speed and exactness without the language as a variable. The harness already exists.Medium
4Capability-safe, agent-generated services. Only if 1–3 justify it: sandboxed plugins or user-defined endpoints, where enforced effects and template safety are the product.This is where Flow's specific properties would matter most.Large

If only one thing carries forward: the evidence says agents already do fine in languages they know. What they lacked was protection against quietly wrong or quietly collateral edits. Build those protections (independent oracles, preservation guards, differential checks) around mainstream languages before considering a new language again.
