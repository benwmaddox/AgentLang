The Campfire port

From 11 October, the project's priority became porting Campfire to Flow and serving it natively. Campfire is 37signals' open-source Rails chat app, MIT-licensed. The read side reached byte-for-byte equality with Rails. The native server runs at 0.6–0.8× the throughput of a hand-written Rust port in a fraction of the memory. The write side and real-time features were not finished.

How parity was proven

Parity was decided by comparing bytes against the running Rails reference on the same database snapshot, not by review. The method:

  1. Run the pinned Rails app on a fixed snapshot, and capture each page and partial with Rails-issued sessions.
  2. For computed fields, run a Rails oracle (rails runner) that prints the reference value for every input. Examples are message presentations, signed IDs and ETags.
  3. Make the Flow server produce the same bytes, with one exception: Rails' CSRF elements, which Flow and Rust both leave out by design.
  4. Keep a page-check harness that diffs every route on every build.

That made "done" objective and caught many subtle details:

  • ERB whitespace and trim rules;
  • Ruby's shortest round-trip Float#to_s for image dimensions;
  • CRC-32 avatar colours;
  • fresh_when's weak ETag: SHA-256 of [messages, template digest], cut to 32 hex digits;
  • ActiveStorage signed blob IDs (PBKDF2, then HMAC-SHA1);
  • Turbo signed stream names;
  • CGI.escape and Rack form decoding;
  • FTS5 porter-stemmed search.

Honest caveat on how templates were produced: the large static markup segments were cut by scripts from Rails' own rendered pages into checked Flow templates. The dynamic holes, the data access and every computed field were written in Flow. It is a faithful port of the behaviour, but not a line-by-line translation of the ERB, and the method relies on having the reference app running.

Performance

This is the fair Linux sweep from report 285. All three servers ran natively in WSL2 on the same snapshot, each pinned to 4 vCPUs, with the load generator on separate vCPUs. There were 3 interleaved repetitions of 6 configurations, every response was validated, and the protocol was declared before the first run.

What the numbers support

  • Uncached, Flow reaches 0.8× Rust's throughput at about 1.4× its CPU per request. Flow serves Rails' exact page; Rust's differs from it by 925 bytes.
  • Memory is a sixth of Rust's uncached, and similar cached.
  • Against Rails: 35–60× the throughput, at about 1/50th of the memory uncached (15 vs ~815 MB) and about 1/16th cached (48 vs ~775 MB).
  • Every cell validated, with zero invalid responses across 72 cells in 282 and every 285 lifetime.

What they do not support

  • Rails never saturated its CPUs (3 puma workers, wait-bound), so the Rails gap is real but not a clean peak comparison.
  • Flow's p99 is about twice Rust's, and cached Flow is at 0.6×.
  • Matching Rails' rich-text pipeline cut Flow's uncached throughput from 3,488 to 1,221 req/s (284 → 285). Rendering uses about 650 KB of arena per message for about 10 KB of HTML.
  • These are the project's own benchmarks on one machine, not an independent benchmark.

What is missing

Campfire is a chat app, and the hard parts of a chat app were not ported.

  • Real-time. There are no ActionCable or Turbo Stream WebSockets, so live message delivery does not exist.
  • Writes on the native server. Posting messages, boosts, POST /searches and clearing, with inbound sanitization. Message creation worked only in the earlier interpreter and .NET slice (242).
  • Sign-in and out on the portable server. A bcrypt decision was made (system libxcrypt on Linux, vendored crypt_blowfish on Windows), but the work wasn't finished.
  • Other pages and parts:
    • account logo upload;
    • room creation with restrict_room_creation;
    • bots and webhooks;
    • push notifications;
    • background jobs;
    • file uploads;
    • asset serving parity;
    • deployment.
  • Approximations.
    • Plain text for lists, quotes and captions (used only for emoji detection and URL comparison).
    • ASCII-only initials upper-casing.
    • Metadata dimensions in exponent form.
  • A typed schema and validated migrations were planned and not built.

Assessment

The port is the project's most convincing artifact. It proves that the language can express a real application exactly and serve it efficiently, and that oracle-driven porting works. It is also where the language's gaps cost the most time. Every missing stdlib function or operator became a detour, and builds took 5–10 minutes for most of this phase. The read side of a chat app is the easy part. Real-time delivery and writes, where Campfire's complexity actually lives, were not reached in 13 days.
