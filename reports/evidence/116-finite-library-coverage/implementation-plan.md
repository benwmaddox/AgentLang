# Finite library coverage implementation plan

Checkpoint: `36f78b2` (effect assertions and the versioned-help adoption report are published). Root-owned edits to `docs/PRD.md`, `docs/FINITE-COVERAGE.md`, and the unrelated retention-trial files were already present and are not part of this plan's source ownership. This is an implementation plan, not a claim that finite coverage is present. No source, test, or frozen evidence files were changed while preparing it.

## Contract to enforce

For every function qualified as `LibraryWord`, retain the current own-instruction and own-branch gate, then require finite return-value coverage and per-parameter finite input coverage from that function's own attached tests. A direct `Bool` input parameter must be observed with both values; a direct enum parameter must be observed with every case. Each input parameter is checked independently, so two Bool parameters do not require all four combinations. Calls in an expectation expression and calls to unrelated helpers never supply the target's values.

For returns, require every value in a supported closed finite domain. The domain evaluator should cover `Unit`, Bool, payload-free nominal enum cases, `Option<T>`, `Result<T,E>`, and finite record products recursively. `Option` and `Result` require every inhabitable tag; finite payloads require every value under each tag. Runtime numbers, strings, floats, money-like numeric records, and lists are open domains, not finite merely because a representation or refinement bounds them. For open payloads, require the variant/tag observations and retain the PRD's boundary-test obligation; do not invent an exhaustive scalar domain. A finite composite above a fixed cap, recursive/unprovable type, or refined scalar whose valid domain cannot be proven must fail explicitly with a structured unsupported-domain diagnostic, never be skipped.

Keep nominal identity in the coverage key. An enum case is `(ProgramTypeKey, caseIndex)`, a scalar is `(ProgramTypeKey, baseValue)`, and a record is `(ProgramTypeKey, field-values-in-layout-order)`. Do not compare display labels alone. For a scalar with finite base and no validator, wrapping preserves a finite domain. With a validator, do not assume all base values are constructible or drop rejected values: either prove the valid subset through verified semantics or report the domain as unsupported. A list is open even when its item type is finite; recursive records are conservatively open/unsupported with cycle detection.

Check each declared output position independently, matching the PRD's per-position output wording. Within one position, finite records/containers remain complete recursive domains (so `Record<Bool,Bool>` has four values); do not form a Cartesian product across separate output stack positions. For mixed finite/open components inside one declared type, record finite recursive values and variant tags while preserving the open payload boundary-test obligation.

Coverage evidence is transient and revision-bound. At test execution, collect target arguments on exact user-function entry and outputs only on normal return. Merge finite observations into qualification results only from passing own tests. A passing expected-runtime-error case can contribute its actual input values, but never a return value. A test that fails its value, runtime-error, or effect-count assertion contributes no finite evidence. The existing isolated expectation trace remains excluded.

## Architecture and owned files

1. Add a pure `FiniteCoverage.fs` module after `TypedIR.fs` and before `Runtime.fs` in `src/AgentLang.Core/AgentLang.Core.fsproj`. It consumes a verified `IrProgram`/`IrFunction` and nominal table, calculates bounded finite domains, canonicalizes observed `Value`s against their declared IR types, and returns explicit `Complete`, `Missing`, or `Unsupported` results. It must not execute user code to guess domains. Use a documented cap (proposed: 4,096 values per expanded domain/product) and a visited `ProgramTypeKey` set; overflow and cycles produce explicit results.
2. Add lazy observations to `IrInterpreterHost` in `src/AgentLang.Core/TypedIR.fs`/`IrInterpreter.fs`: `EnterUserFunction: WordId -> int -> (unit -> Value list) -> (unit -> unit)` and `ReturnUserFunction: WordId -> int -> (unit -> Value list) -> unit`. `executeFunction` passes deferred decoders for actual inputs and the normal output stack; it always calls the existing entry cleanup from `finally`. `invokeResolved` performs effect preflight before entry, so denied preflight cannot count. Hosts that ignore the thunks (including retained/native-mailbox paths) do not decode or allocate observer payloads. The existing tests that construct hosts need no-op callbacks; direct hook tests are owned by the separate IR-test worker.
3. In `Runtime.fs`, give each test trace an exact observation target from the test owner's `WordId` and current revision, independently of whether that test has an effect assertion. Invoke the lazy value thunks only when callback identity matches. Add typed per-parameter inputs and normal returns to `TestCaseResult`; compute finite coverage by folding only `Passed` results whose `Word` is the library owner. Keep the existing `instructionsCovered`, `branchesCovered`, and related JSON fields unchanged; add finite input/return data alongside them only where relevant. Do not change no-suffix test JSON shape.
4. Centralize the structural-plus-finite library check and call it from all maturity-preserving paths: commit/promotion (`Runtime.fs` around 2,895–2,968), replacement source staging (`2,648–2,658`), Flow library maturity (`3,679–3,685`), rename/rewrite (`4,594–4,621`), and deprecate (`4,737–4,752`). A path must evaluate tests against its exact proposed snapshot before publication; failure leaves the durable manifest, current body, and revision unchanged. When replacing a dependency, run the affected persistent callers' own tests and revalidate any caller still marked library; current commit collects `callerResults` but only gates selected words structurally. New finite evidence must not remain stale after a helper revision changes.
5. Preserve the current structural diagnostic contract and add stable finite diagnostics with expected/missing typed labels. Proposed codes are `LIBRARY_FINITE_COVERAGE_INCOMPLETE` for missing values and `LIBRARY_FINITE_DOMAIN_UNSUPPORTED` for an unprovable/capped domain. Keep enum-constructor/match support for a word's own verified body once its own finite signature and branch evidence pass. Retain a guard for enum references reachable only through a user helper until each helper is independently qualified and a separate dependency-closure check proves that qualification; this slice must not make a primitive-signature wrapper qualify by calling an unchecked enum helper. Generated nominal constructors are covered through their caller's verified signature/body, not treated as an unchecked user helper.

## Persistence and legacy libraries

Finite observations need no manifest/source schema field: they are recomputed from exact durable tests and the current verified program on each fresh engine. Existing source/manifest format versions can remain unchanged if old projects still parse and compile; that does not mean an older runtime can implement or validate newly supported library enum contracts. Renames/revisions must re-run current attached tests against the new stable ID/revision; tests or observations from the prior revision never carry over.

There is no persisted proof that a pre-feature `LibraryWord` met the new finite gate. Leaving such a word trusted after reload would grandfather it. Fail closed during Engine initialization: recompute the gate for every durable library word from its own attached tests and the exact loaded program; if any fails, return a structured initialization diagnostic and do not construct an Engine. Preserve the source and manifest bytes; do not silently demote the word or rewrite storage. This can prevent an old project from opening until its source/tests are repaired, which is an explicit compatibility limitation of enforcing the new contract without a repair-mode feature. Add a test for an old library fixture with a branchless Bool return and one attached true test: fresh reload must fail with a finite-coverage diagnostic and leave the manifest untouched.

## Existing fixture impact and integration risk

Existing branch coverage alone will not satisfy the new return/input requirements. The current tests already contain useful positive and negative baselines: `tests/AgentLang.Flow.Runtime.Tests/Program.fs` has a direct Bool input library with true/false tests (`library.case_only`, around 1,658–1,675) and a Bool-input branch fixture where expectation-only calls must not count (`coverage.same`, around 2,047–2,084). `tests/AgentLang.Acceptance/Program.fs` has constant Bool-return helpers (`choose-true` and `choose-false`, around 1,488–1,510), and Option/Result tag coverage (`option.library-default` and `result.library-value`, around 2,145 onward). The latter Result has infinite payload domains, so tag coverage is compatible but its explicit boundary-test policy still needs to be defined. `tests/AgentLang.Business.Language.Tests/Program.fs` and `tests/AgentLang.Business.Transitions.Tests/Program.fs` aggregate-commit whole business libraries (around 656–710, 795–832, and 1,090–1,105); these include Bool and Result-shaped helpers and will be affected by an exact full gate. The separate fixture auditor should classify each affected owner and add or narrow tests/contracts; do not weaken the new gate to preserve old success expectations.

The largest risk is rollout, not the observation hook: existing branchless Bool-return library helpers that only assert one constant result will fail. A finite record/composite domain can also grow quickly, so the cap and diagnostics need focused tests. `Result<Int,String>`, records with numeric fields, and `Option<List<T>>` are open payload domains and must not be mistaken for finite exhaustive values. Meaningful boundary tests for these open payloads remain a human/acceptance obligation; this slice must not imply that a universal boundary policy has been mechanically enforced or block every Int-returning word.

## Acceptance tests and validation

- Branchless `Bool -> Bool`/`() -> Bool`: only true fails with false listed; adding a passing false test succeeds. A constant Bool function whose declared return cannot produce both values remains a project word, proving no unreachable-value exemption.
- Two Bool parameters: both values observed independently succeeds without requiring all four pairs; missing one value in either parameter fails. A Bool in a pure expectation expression, a caller test, or a helper invocation does not count.
- Enum input and return: cover every case; same label under a different nominal key does not satisfy coverage. Missing direct input or output case fails with typed labels.
- Unit and finite composites: Unit, Option<Bool>, Result<Bool,Unit>, and finite records exercise every finite value/tag. A scalar validator with finite base is either precisely enumerated under verified constraints or explicitly rejected; record/option/result recursion and cap overflow are bounded.
- Open composites: Result<Int,String>, Option<List<Bool>>, and a record with numeric fields require all tags/variants but do not enumerate scalar/list payloads. Add tests for approved boundary-policy behavior; until defined, report this as a remaining PRD gap rather than claiming complete coverage.
- Failed test does not count: wrong expected value, unexpected/expected runtime-error mismatch, effect-count mismatch, and expectation-only calls leave the finite gap. A matching expected runtime error records input but no return. Repeated target calls and calls through nested helpers aggregate only exact target entries; preflight denial records zero; target fault always executes cleanup.
- Lifecycle: missing finite values block first library commit, Flow library maturity, same-ID replacement, rename/rewrite, and deprecate atomically. Replacing a helper causes affected library callers to be re-tested and revalidated. After commit, rename, and fresh reload, source/test bytes remain durable and coverage is recomputed for the current revision.
- Legacy/no-feature compatibility: Flow/1 source and old manifests still load according to the explicit stale-library policy; source without finite requirements retains the old structural JSON fields and current passing behavior. No ABI layout or frozen Release artifact changes.
