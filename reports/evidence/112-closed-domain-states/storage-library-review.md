# Focused enum storage and library-guard review (read-only)

Scope: current `Runtime.fs`, `Storage.fs`, `FlowLowering.fs`, `FlowRewrite.fs`, and `Source.fs`. This review excludes the known in-progress `MakeEnumCase` reconciliation fix, native backend, and finite-value coverage implementation. No production edit or build was performed.

## Findings

No reproducible storage contract regression or transitive library-qualification bypass found in the inspected paths.

- Durable type identity: Flow/2 enum source is stored as the existing version-3 type-source object (`Runtime.fs:3156-3174`) with its source format and content hash. Reload reparses exactly one matching enum only for Flow/2 (`Runtime.fs:1595-1629`), checks authoritative canonical rendering and metadata (`Runtime.fs:1874-1905`), and rejects a validator target on an enum (`Runtime.fs:536-553,876-883`). Flow/1 enum declaration itself fails `FLOW_SYNTAX_VERSION` (`FlowParser.fs:993-999`); Flow/1 enum matching fails the same syntax-version check (`FlowSyntax.fs:384-389`). No manifest version bump is needed for another Flow/2 type-source object.
- Call-binding identity: `FlowLowering.fs:1544-1547,1617-1620` and `FlowRewrite.fs:104-107,485-495` use the same `EnumScrutinee` and positional `EnumCaseStatement(caseIndex,statementIndex)` paths. `Storage.fs:434-435,448-450,478-479,610-625` round-trips both indexes and bounds them. `Storage.fs:942-954` rejects those new path tags on Flow/1 revisions, including a forged manifest; the source reparse and binding reconciliation still determine whether a path actually denotes the same call. Case reordering is outside a rename-only rewrite and must create new bindings through normal replacement.
- Library gate: `Runtime.fs:136-185` walks `TNamed` signatures recursively through list/option/result, record fields and scalar bases, explicit container type arguments, enum constructors, every reachable user-word dependency (with a visited set), and any `MatchEnum` marker. `Compiler.fs:545-557` traverses enum arms for call dependencies. Primitive specializations cannot hide an enum value: a source path to one must originate in a signature, container annotation, generated constructor, match, or reachable helper, all covered by that walk. `Runtime.fs:481-486` checks only authored words with `LibraryWord` maturity; generated enum constructors are intrinsic generated words and are outside this authored-word qualification gate, like existing generated record/scalar words.
- Gate call sites: the guard runs when an existing library word is redefined from Stack or Flow (`Runtime.fs:2544,3573`), on selected candidates after proposed library promotion and before durable commit (`Runtime.fs:2779-2790`), after rename/rewrite (`Runtime.fs:4485-4490`), and before library-word deprecation (`Runtime.fs:4634-4640`). Thus replacement or rename cannot silently retain library maturity while acquiring an enum dependency. Persisted sources reload through the same compiled snapshot; a hand-edited source object's hash/canonical mismatch is rejected.

## Focused validation to request before integration

1. Flow/2 project with enum constructor call in a match scrutinee and another call in an enum arm: commit, reload, and rename a called helper; verify resolved target identities and paths survive. Mutate a manifest Flow/1 binding to `enumScrutinee` or `enumCaseStatement` and require `STORAGE_INVALID_MANIFEST`.
2. Reject `library=true` for an authored word that reaches an enum via each of: `List<Option<Enum>>`/`Result` signature; record field containing enum; explicit typed container body; generated `Enum.case` call; transitive helper call; a `MatchEnum` with otherwise scalar output. Verify `LIBRARY_FINITE_COVERAGE_UNSUPPORTED` and unchanged staged/persistent state. Also reject replacing or renaming an existing library word into one of these paths.
3. Preserve legacy Flow/1 and Stack source objects byte-for-byte in existing frozen fixtures. Add new Flow/2 fixtures for enum persistence; no migration of historical business status examples is required.

The guard intentionally blocks authored enum-bearing library words until finite-value coverage exists. It does not claim such coverage now.
