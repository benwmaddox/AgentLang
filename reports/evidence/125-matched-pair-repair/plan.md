## Design fixed before dispatch

Run two independent Luna/max actors per condition: retained-domain Flow/2,
reset-domain Flow/2, and conventional F#. Each of the six actors receives an
isolated copy, the same public task and the same twelve-case acceptance oracle.
This is bounded replication, not a statistical superiority test. Reset is the
compact one-word/three-type foundation from report 111, not a rich dictionary.
Retained contains the actual agent-created queue-once function from report 111;
conventional receives its accepted equivalent helper. Foundational types, path
contracts and provider semantics are aligned. The new pair target starts inline
in every arm with the same early-return bug. Helper availability is the study
contrast, not an actor prompt hint.

The pair workflow processes both invoices independently, first then second.
Aliased identifiers observe preceding state changes. An ineligible first invoice
must not suppress the second. The public contract defines exact status matching,
content preservation, result order, provider effects and capability preflight.
The root independently enumerated twelve oracle scenarios before dispatch.
Predispatch review changed the second-slot ineligible case to `Open` to cover
case-sensitive matching in both positions; prior scores are retained separately.
Correctness is not inferred from actor-authored tests.

The four newly supplied target cases have matching inputs and return-only
assertions in all arms. Inherited helper tests remain the actual earlier actor
outputs and differ in assertion strength; report that limit. Seed tests must pass
while encoding the bug. The Flow target must qualify as a
library without relaxed gates. Both Flow arms use identical target source; reset
lacks the learned helper. Conventional keeps nominal wrappers and an explicit
provider. Report remaining fixture and helper differences precisely.

Actors inherit no conversation and may not access another arm. Each launches one
broker, limited to 100 exchanges. Flow/2 help is explicitly selected and verified.
Edits use only the actor's broker and project. These access restrictions are not
an OS isolation claim. Run at most three actors concurrently and do not coach
after dispatch.

## Acceptance and evidence

Before dispatch, pin snapshots, prompts, runtime, oracle, broker and scorer.
Require passing seed tests, independent rejection of the seeded bug, and
acceptance of a separately corrected control. Check the wrong-second-input and
needless-write mutants against the oracle. Reuse existing broker and verifier
mechanics; do not add a general harness or runtime features. Build F# outputs
fresh; copy and pin the existing frozen Flow runtime without rebuilding it.

After each actor closes, independently reload a copy and check all twelve cases,
including complete filesystem state, provider counts and denied capabilities.
Report own tests, maturity, preservation, actual helper calls, source/test edits,
structured errors, contained test failures and session timing separately.
The oracle verifies ordered returned values, full state and aggregate effects;
these do not prove provider-event order. Inspect submitted source/IR execution
order separately and mark it unverified if ambiguous, without claiming an event
trace that does not exist. Protocol success is not test success. Hash the original actor project before and
after scoring. Provider token usage is unavailable unless returned authoritatively.

Two predeclared post-solution mutations run only on copies: derive the second
reminder path from the first invoice identifier; write an existing second marker
back unchanged. Report
actor-test/library-gate detection separately from independent oracle detection.
Coverage percentages do not establish assertion strength.
