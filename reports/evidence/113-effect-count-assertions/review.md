# Focused effect-assertion design review at 404a7a4

Read-only scope: `minimal-design.md` against the committed interpreter/test runner. No production edits or build. These are the minimum implementation pitfalls and focused tests; no broader effect framework is needed.

1. **Keep value/error and effect failures independent.** `Runtime.fs:90-99` has one `TestCaseResult.Error`, and `checkedByTest` (`Runtime.fs:1999-2088`) uses a broad `try/with LanguageException`; its `=> error CODE` path can mark the test passed from the caught code. Run the actual body once, derive the legacy value/runtime-error outcome exactly as before, then compare scoped counts as a separate non-throwing result. `Passed` is the conjunction. Preserve the legacy top-level `errorCode` for a value/error failure and add an assertion-specific structured object for the effect mismatch; when effect failure is the only failure, top-level `TEST_EFFECT_ASSERTION_FAILED` may also be emitted. A wrong return **and** an extra write must expose both failures. A mismatch must never be caught as the expected runtime error.
2. **Scope to the verified target, including nested/callback calls, and close on faults.** `IrInterpreter.fs:408-420` resolves and revision-checks `UserWordTarget` after `PreflightEffects`; `executeFunction` at 435-444 is the common entry for direct, helper-mediated, and list-callback user calls (`IrInterpreter.fs:703,728,744,772`). Start the depth scope only after the exact `WordId`/revision is verified, increment target invocation count for each entry, use `try/finally` around execution, and count a provider event once whenever depth is positive. A preflight failure before entry leaves zero invocations and must fail an opted-in assertion even when expected counts are all zero. Repeated target calls aggregate; recursive/reentrant calls increment depth but do not double-count one provider event. One fresh trace per test prevents cross-test leakage. Do not identify the target only by `CoverageTarget` display name.
3. **Do not overclaim setup isolation.** The actual trace includes setup (`Runtime.fs:2001-2008`), while the separate pure expectation trace has `CoverageTarget=None` (`Runtime.fs:2048`). Increment scoped counts only from `InvokeEffect` (`Runtime.fs:1509-1525`) while target depth is positive. This excludes setup provider calls and unrelated helper calls *outside* target execution; a genuine target invocation used as setup is indistinguishable from an exercise call and counts. If the product contract requires excluding that invocation by intent, an explicit exercise marker is required and is outside the current minimal design. Keep `Compiler.fs:513` rejection of effectful expectations (`TEST_EXPECTED_VALUE_EFFECTS`), including effects in an unselected branch.
4. **Use the observable effect subset.** `TypedIR.fs:27-63` declares ten effect names, but this runtime's `InvokeEffect` exposes/counts only `fs.read`, `fs.write`, `clock.read`, and `console.write` (`Runtime.fs:1512-1525`). Accepting `db.read: 0` or similar as an exact assertion would misleadingly certify a category with no provider. Restrict this first syntax to those four categories, with an explicit unsupported-effect diagnostic; omitted observable categories mean zero. `FlowParser.fs:93-145` tokenizes `fs.read` as identifier, dot, identifier, so parse a dotted effect key deliberately (like its existing `parseEffects` at 880+) rather than calling `expectIdentifier` once. Reject duplicates, negative/noninteger/oversized counts, and suffixes on Flow/1/examples.
5. **Preserve ownership, trust and legacy responses.** Flow attachment-only documents reject primitive/generated owners (`Runtime.fs:3598-3617`), and new Flow project tests must attach to a word declared in the same document (`Runtime.fs:3210-3240`). Add an assertion-specific lowering/compiler owner check anyway; a malformed or future path must produce a clear diagnostic, not zero observations. The annotation is metadata only: keep `PreflightEffects` and capability/effect declarations unchanged, and count only actual provider callbacks, including callbacks that fault after attempt (`Runtime.fs:1512-1515`). Add `effectAssertion` fields only when opted in; existing test results and `test`/`test-all` payload keys stay byte-shape compatible otherwise. Persist the suffix in the canonical Flow/2 test source and verify reload replays it without a manifest bump.

Focused test matrix: direct target and nested helper/callback effect counts; setup write before/after target excluded; two target invocations aggregate; expected file-not-found counts attempted read and closes scope; preflight/zero-target invocation fails; wrong returned value plus extra write retains both diagnostics; pure expectation and an effectful expectation rejection; generated/primitive owner rejection; malformed/unsupported effect keys; one old test without suffix retains its exact JSON shape; script-derived extra-write control fails an asserted `fs.write: 0` while its legacy return test still passes. Library replacement must reject the failed attached assertion without changing capability policy.
