# Owning-stack-002 contract review

Status: bounded contract approved for implementation on 2026-10-08 after reading `.agentlang/owning-stack-002/implementation-plan.md`; no implementation source edits or tests in this review. Also reviewed `.agentlang/owning-stack-002/plan.md`, `TypedIR.fs`, `IrInterpreter.fs`, current `OwningStackAot.fs`, and ABI1 `owning_stack_runtime.[ch]`. The published plan freezes ABI1-preserving immutable type/field descriptors, an explicit containing-owner bound for scans, backend-only depth cap, F# packed-local metadata, and no payload heap scratch.

## Blocker to settle before dynamic emitter edits

The fixed emitter reserves `max(argumentBytes, outputBytes)`, moves outputs one by one to `%result.destination`, then releases to `frameBase` (`OwningStackAot.fs` around lines 1482-1530). Dynamic output lengths make that sequence unsafe: copying the first result may overwrite a later result's source, and releasing to the old frame base can erase a result larger than the consumed argument span. The published plan resolves this by measuring total actual output extent, reserving exact bounded staging above outputs, transferring the complete range to staging and then as one range to the caller destination, and releasing only above `destination + actual_output_extent`. This is approved as a contract, contingent on implementation preserving the stage and accounting for its peak cursor/move bytes. The high-value regression remains two outputs with first larger than the argument span and second a distinct sentinel; zero outputs must not synthesize a token, while an empty-record output remains an eight-byte token.

## Implementation checks against the approved plan

- Packed local replacement is specified as preflight, growth reserve, complete suffix shift including the top source, install, consume old source, and success-only metadata commit. Check implementation's relocated source offset and aggregate live/local delta for both growth and shrink while later locals/operands live; preserve scope-shadowed outer owner and poison/reclaim exact removed bytes. A max-sized local slab or pointer back to a host/callee buffer does not meet the ownership goal. Direct C shorter-then-longer replacement and same-LocalSlot shadow cases should pin this.
- The plan freezes bounded scalar metadata `{active, offset, extent, payload}` per local in the generated frame, with bytes reported separately from payload stack. A `StoreLocal` source at the operand top participates in suffix shifts; compute its new offset after each successful move before copying into the slot. If any later helper fails, branch straight to the captured baseline cursor/live/reservation unwind and do not consult partially relocated metadata.
- The descriptor/scanner plan has acyclic verified record graph, depth 64 gate before native entry and raw scanner guard, checked field count/index/offset arithmetic, and a source *owner* limit on every nested scan, not just overall stack capacity. Verify raw tests reject a forged String length that reaches an adjacent owner under global cursor, plus malformed descriptor links/cycles and unknown type ids, before byte reads.
- All temporary storage used by `string.concat`, record compaction, local insertion, and return overlap must be within the capacity-accounted stack, or bounded metadata whose size appears in instrumentation metrics. The caller's retained stage is bounded and committed only after complete decode. No shared graph, reference pool, unreported heap allocation, or retained pointer is allowed.
- Host codec must write/read raw UTF-16LE code units, including isolated surrogates and embedded NUL. The existing semantic IR accepts any non-null `LString`; interpreter `string.length` uses `.Length` code units and `string.concat` concatenates those units directly. UTF-8 conversion, replacement, scalar-value validation, or normalization would change verified program behavior.
- If ABI1 context/event struct layout is unchanged, keep its exact size/offset marshalling assertions. If changed, bump ABI version and audit C, LLVM declarations, F# marshalling, raw tests, fixture/report schema. Fixed public `PayloadBytes`/`ExtentBytes`/`OffsetBytes` must not present dynamic minimum or one runtime instance as a fixed type size; mark dynamic metadata explicitly while preserving `compile` and `ExecuteInto` call shape.

No remaining contract blocker was found in the written plan. Later optimization: static fast paths, fewer memmoves, and narrower metadata can follow correctness evidence. They do not justify weakening the first dynamic ownership fixture.

## Shared-DAG traversal and depth follow-up

The current C `al_owning_validate_type_graph_inner` (around lines 559-698 in SHA `4670F175...`) recursively revalidates every child without remembering completed descriptor subgraphs. A depth-63 chain in which each empty record has two zero-width fields of the previous type is small as a descriptor graph but causes exponential validator work. The depth cap alone bounds stack recursion, not total work. The C owner is replacing this with a fixed-bound tri-color/memoized descriptor traversal and cached subtree height. Review the landed version for `O(type_count + field_count)` work, gray-cycle rejection, and `currentDepth + cachedHeight <=64` on every black/cache reuse. Use a fixed descriptor-count ceiling and fixed-size automatic metadata (no heap/VLA), and report scanner cache bytes with bounded instrumentation. A scalar visit budget would be simpler but would reject valid shared DAGs beyond an arbitrary work threshold; memoization is preferable if its storage is explicit.

Separate F# pre-native blocker in the current in-progress `OwningStackAot.fs`: `buildType owner depth` rejects cache hits when `depth + LayoutDepth > 64`, but misses only when `depth > 64`. A unique leaf first reached at depth 64 is admitted, and its parents can produce `LayoutDepth=65` without a final aggregate guard; C rejects depth index 64 (`depth >=64`). Reject a miss at `depth >=64` (root is depth0) and/or assert `depth + computed LayoutDepth <=64` before caching. A unique 64-node chain should pass and 65-node chain should fail before native entry; separately test shared cached subgraphs at a deeper path.

Material test gaps sent to C owner:

- `dynamic_return_larger_than_arguments` transfers one output only. Add a two-output contiguous return: first variable result wider than the argument span, followed by a distinct scalar sentinel, then check both bytes/values and final cursor. - `dynamic_local_suffix_compaction` does physically shift a younger scalar and String for shrink/grow, but it uses `copy_external_bounded` and manual `update_live`, without local store/clear/reservation accounting or same-slot shadow ownership. Add header-rejection cases with tiny backing arrays. The nested record copy's `memcmp(stack, helperBuiltExternal)` checks copying but is not an independent layout oracle; pin one complete literal nested String/record byte buffer in addition to its current offset/tag checks.

These are validation gaps rather than demonstrated C storage defects. Keep final O0/O2/UBSan results separate from this source inspection.

The direct-test aggregate later reported peak live operand payload 82 with a 64-byte stack. Source inspection localizes this to the manual replacement sequence in `dynamic_local_suffix_shrink`: long State payload 34 + younger Int 8 + empty String 8 = 50, then `copy_external_bounded` adds short State payload 32 into the still-accounted old slot, transiently reporting 82; only afterward does `update_live(-34, 0)` remove the old owner. Grow analogously overlaps old/new accounting. This is an invalid ownership sequence in the fixture, not a legitimate peak or a metric to suppress. Invalidate the old owner before installing the replacement (or use a net-delta transfer helper), track local versus operand ownership correctly, then pin `peak live <= physically occupied initialized owner extent` at stable points. A real F# replacement integration case remains necessary.

## Dynamic emitter review (source in progress)

Reviewed `emitDynamicModule` in `OwningStackAot.fs` as it changed from SHA-256 `3F1F6CCA...` to `9CEDAC2B...`; this is source inspection, not a claim of successful native execution. One concrete entry-wrapper bug was found and fixed by the F# owner: after reserving the whole input prefix, the generated loop copied every input to the context cursor (the end of the prefix), which `al_owning_copy_external_bounded` rejects for any nonempty value. The current loop uses the measured `sourceOffset` as destination (around line 2975).

Packed-local removal/replacement shifts the complete later-local-and-operand suffix and updates active local offsets only after successful moves. A helper failure branches to aggregate frame-baseline unwind rather than reading partly relocated metadata. `If` joins phi-merge runtime extent/payload for each operand while both arms use shared local metadata; `Scope` clears only its own flags and restores outer bindings/types, matching the verifier/interpreter's discarded scope-local map. The call path transfers the whole contiguous output range below the caller's arguments before release, preserving a later sentinel when the first output grows; the zero-output case transfers zero bytes and removes argument bytes. A standalone empty record remains eight bytes, while nested zero-width fields consume no bytes.

`StoreLocal` currently reserves an additional shift window for growth even when the top operand is the only suffix value (around lines 2355-89). This can raise peak capacity above the stable final cursor, e.g. first 8-byte local store requests 16 bytes. It is an accounted temporary in the specified algorithm, so it is a later peak optimization, not a correctness blocker. Capacity fixtures must compare against the emitted staging schedule. A focused mixed `[Empty, String, Int]` record fixture should pin standalone Empty8 collapsing to nested width0, String padding, the later Int sentinel, and Empty projection rematerializing its token; the current construction/projection code appears structurally consistent with this layout.
