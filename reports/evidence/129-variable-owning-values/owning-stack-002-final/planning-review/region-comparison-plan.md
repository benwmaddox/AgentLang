# Scope-region comparison, bounded proposal

Use the same verified `IrBlock`, input bytes, UTF-16LE value encoding, native C runtime, retained-output commit, and diagnostics as the packed dynamic emitter. Add one internal placement choice inside `OwningStackAot.fs` (`Packed` or `ScopeRegion`) so both variants share validation, scanners, primitive lowering, and the runner. Finish the packed candidate's correctness run before using it as a comparison arm. This is a comparison, not a backend or source-language pivot.

## Smallest credible region lowering

Keep one physical buffer and cursor. Active operand values remain a contiguous suffix at the cursor; local metadata continues to hold explicit offset, extent, payload, and active bit. A `StoreLocal` retires an old same-scope owner in place with the existing `al_owning_clear_local` and `al_owning_local_release`, leaving its poisoned bytes as occupied dead space. The new top operand becomes the local owner at its current offset by transferring payload accounting from operand to local and reserving its extent as an active local. If earlier operands remain below it, reserve exactly their total extent, move that whole operand prefix above the new local, and poison their old locations. This is required to keep the operand suffix contiguous; a proposal that simply leaves the local above older operands would break current `drop`, call-argument, and offset lowering. Thus the region policy reduces repeated packing of locals but is not movement-free: stores with surviving older operands still move those operands, and boundary results still transfer. `LoadLocal` still makes an independent full copy at the cursor. A replacement need not move younger locals or fill the old hole.

At entry to each `Scope`, capture the start of its incoming operand suffix as the region base, plus the outer local bindings. At successful exit, clear active child locals, move the complete surviving operand suffix to that base, then release the cursor to `base + actual surviving operand extents`. This transfers results to outer-owned storage and reclaims all holes and dead locals from the region in one rewind. `TypedIR.fs` Scope verification restores its incoming `LocalTypes`, and `IrInterpreter.fs` discards the inner block's returned local map, so a store to the same `LocalSlot` inside a child is a discarded shadow; its outer owner stays below the region base. No child-local mutation should be promoted to the outer frame. The implicit root function region uses its frame base as the result destination before leaving the frame; a callee still returns a contiguous result range for the existing whole-range caller transfer. Empty output has length zero, while a standalone empty-record output has its eight-byte token. Branches may have different cursor and local offsets; shared per-local metadata and the cursor-derived operand start must join after both arms without assuming matching physical offsets. On error, use the existing frame-baseline cursor/live/reservation unwind; no local metadata is consulted after a partial transfer.

This route mainly replaces packed `emitStoreLocal`, `removeLocal`/`emitClearEnvironment`, and `emitEntryOffset`/cursor checks in the dynamic emitter. The operand start can be computed as `cursor - sum(actual operand extents)`; no new payload pointer or second arena is needed. Existing C `clear_local`, `move_range`, `release_to`, live accounting, and local reserve/release are sufficient if the emitter's success/failure sequencing keeps owner counters exact. The region base and per-local metadata are bounded generated scalar state. Retired holes count against stack capacity until the scope/root boundary; they are not reusable by bump allocation before that boundary. Report peak cursor separately from live payload and active local extents. Do not hide holes by lowering the recorded peak or allocating a second unreported buffer.

## Why boundaries matter

Naively appending each replacement without a scope/root rewind makes dead holes accumulate through repeated stores; a finite straight-line body has a finite bound but can still exhaust capacity earlier than packing. The currently supported native subset has `Scope`, `If`, and user-word calls but no loop opcode; recursion is depth-bounded, while future loops would make missing rewind more consequential. Completed sibling calls should *not* accumulate callee holes: each callee must transfer results to caller-owned bytes and rewind its entire frame. An inner scope must similarly transfer surviving results and rewind before a later sibling scope or call. Field projection remains a separate parent-consumption operation and may still move the chosen field; the region policy does not eliminate that copy.

## Discriminating cases and measurements

Use three or four same-IR interpreter/native cases, with O0 and O2 native builds and an independent result-byte oracle:

1. `StoreLocal` of short, then long, then short `String` in the same slot while a younger local and a live operand exist. Check independent `LoadLocal` copies and final values; this exposes packed suffix moves versus retained holes and capacity peaks.
2. Two sibling nested scopes shadow the same `LocalSlot`, each producing a String result consumed outside; include a branch with different String lengths. The second scope's entry cursor must return to the pre-scope baseline, and the outer owner must survive both.
3. Construct `[Empty, String, Int]`, project String and then the later scalar in separate runs. Pin zero-width nested Empty, dynamic offset/padding, standalone Empty token on projection, and any field-selection transfer cost.
4. User call with an 8-byte argument and two outputs: a String larger than the argument span followed by a distinct Int sentinel. Check whole-range return transfer, caller-owned result, zero-output sibling call, and failure cleanup.

For each, record exact output values/bytes, peak occupied cursor, live operand/local payload, active local reserved extent, move bytes by event kind, deep-copy bytes, retained-copy bytes, and capacity success/failure at a shared capacity plus a sufficient capacity. Include native elapsed time only after correctness, with identical toolchain/optimization and warmup; capacity thresholds may differ because layouts differ. A tiny capacity microbody should verify required/available diagnostics and that the caller's retained output is unchanged on failure. No performance conclusion follows from the packed variant alone.
