# Independent review of the reminder Flow/2 comparison

The reported observations are supported by the frozen artifacts, with important limits on comparison.

## Claims that check out

- `results/flow-trace-summary.json` lists 22 forwarded broker exchanges for the **corrected** fresh Flow actor. `logs/flow-actor-r2.trace.jsonl` ends with `exchangeCount:22`, `terminationKind:host-close`, and host/runtime exit codes 0. The actor had two recoverable protocol failures (`DISCOVERY_INVALID_ARGUMENT`, `FLOW_SYNTAX_VERSION`) before the successful define/test/commit path. `results/flow-submitted.agent` contains one target function, four attached tests and an example. The independent Flow verifier records 126/126 passed checks and `20/20` own instructions plus `4/4` branch outcomes. Its fresh-process tests, persisted Flow/2 source and library status, effect declaration, snapshot reload, and seed preservation checks pass.
- `results/conventional-trace-summary.json` lists 8 forwarded F# broker exchanges; the raw trace ends with host/runtime exit codes 0. One patch failed with `HASH_INVALID`, followed by successful patches and `validate`. `actors/conventional/SelfTests.fs` runs two preserved seed checks and four actor-owned tests, then a runnable example. The independent F# verifier records 34/34 passed checks. `Domain.fs` and the project file match the seed byte-for-byte; `Operations.fs` and `SelfTests.fs` changed as permitted.
- Both implementations follow the public behavior on shared independent probes: exact `open` status; one existence read and one write for a missing marker; existence plus content read and no write for an existing marker; repeat and second ID; preservation of a custom marker; no provider effects for non-open cases; capability denial before effects; fresh-process state restoration. These are tested through different virtual-provider interfaces and are not identical execution mechanisms.

## Limits that the report must retain

- The authored test oracles are unequal. `results/flow-submitted.agent` asserts returned strings only. Its setup writes marker files, but the attached tests do not assert provider call counts or resulting state. `actors/conventional/SelfTests.fs` asserts returns, read/write counters and state for its own cases. The **independent** Flow verifier closes much of that gap with exact effect counts and stored-marker checks. Thus source-authored tests alone do not support equivalent effect/state test strength.
- The independent verifiers are also asymmetric. The F# verifier explicitly probes an existing **empty** marker, all three separate permission-denial shapes, and swapped nominal `InvoiceId`/`InvoiceStatus` compile failures. The Flow verifier probes a custom nonempty marker, one denied-capabilities case and plain-String rejection for `Invoice`. The Flow code's `file::read(path)` path should return empty content unchanged, but the frozen Flow acceptance did not directly exercise it. The source and shared probes support correct behavior, not identical case coverage.
- `126` and `34` are counts of heterogeneous verifier assertions, not matched behavioral cases. The Flow count includes many content-hash, manifest, response-count and process-exit checks. Exchange counts likewise include discovery/help and recoverable errors, and the brokers offer different operations. Neither metric establishes speed, token efficiency, productivity superiority, or language superiority. There is no controlled token/latency denominator (`results/outcomes.json` agrees).
- The seeded helper was explicitly required by both public prompts: Flow had to call `invoice.reminder-path`, and F# had to use `Invoice.reminderPath`. This is demonstrated reuse, not spontaneous discovery or a language-specific reuse advantage.
- `logs/flow-actor.trace.jsonl` is an earlier **infrastructure-only** failed Flow launch. `prompts/flow.md` supplied incompatible interactive `--frontend/--syntax-version` CLI flags and omitted `help` from the allowed operations while recommending it. `results/flow-launch-correction.json` records two requests, unchanged project state, an independently reproduced CLI error and a fresh corrected actor. Count that attempt separately; do not present it as a failed implementation or erase it from the study history.

## Scripted extra-write negative control

`results/extra-write-control-plan.txt` describes the mutation and expected failure before `results/extra-write-mutant.agent` was written (file times 01:35:32 and 01:36:20 UTC). The source diff against `results/flow-submitted.agent` changes only the existing-marker arm: it stores `file::read(path)` in `current`, calls `file::write(path,current)`, then returns `current`. The added write preserves returned text while violating the contract's no-write rule for an existing marker. This is a scripted disposable-copy control, **not another agent outcome**.

`logs/extra-write-control.responses.jsonl` shows the replacement staged and committed as revision 2 after the same four attached tests passed; its structural coverage is `25/25` instructions and `4/4` branches. The copied project's description still says `maturity:library`. The frozen independent Flow verifier then rejects it: `results/extra-write-acceptance.json` fails at "repeat with existing queued marker exact provider effects", observing two reads and **one write** where two reads and zero writes were required. This demonstrates a concrete gap in the authored return-only tests and structural library gate, and a concrete detection by the independent effect oracle. It does not quantify a general defect rate or compare languages.

The control's final project is `controls/flow-extra-write`, with manifest hash `efafec...`; the productive actor remains under `actors/flow` with the original `c8d75...` manifest hash in its current pointer, matching `results/flow-acceptance.json`. The control neither changes the productive actor's revision nor contaminates its acceptance result.
