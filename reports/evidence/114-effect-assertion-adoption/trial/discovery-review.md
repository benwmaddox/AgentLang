# Post-actor discovery review

This is a read-only diagnosis of the completed 27-exchange actor trace, not another trial or a verdict on whether the effect-assertion feature works.

The actor made five help requests. Four succeeded: bare `help`, then `define`, `examples`, and `replacement`; every successful request omitted `syntaxVersion`, and each response reported version 1. The fifth requested unknown topic `task` and returned `HELP_UNKNOWN_TOPIC`. `AuthoringHelp.parseRequest` defaults an omitted help version to 1 (`src/AgentLang.Core/AuthoringHelp.fs:116-118`), while the Flow/2 effect-count test contract is only appended by `contentForVersion` when version 2 is selected (`:356-405`, especially `:392-404`). Thus the actor's `examples` help did not display the assertion suffix or example. The version-1 authoring and define responses mention `syntaxVersion` for authoring but do not directly say to send it on a *help* request; the prompt's own useful-request list also shows `{"op":"help"}` without a version selector. This is a discovery confound despite the prompt's repeated Flow/2 instruction for `define`/`eval`.

Observed nonadoption is narrower than a language failure. The actor repaired the word and attached a new `existing-marker-not-rewritten` test that writes a custom marker, calls the target twice, then checks the stored text. That test is return/state-only and would pass if an identical-content extra write occurred. It used no `effects { ... }` test suffix. This actor did not discover or adopt the effect assertion contract; the trace cannot establish that it would fail after seeing Flow/2 help. The frozen behavioral verifier and disposable mutant check determine outcome independently.

The smallest next correction is to present version-matched help without teaching the suffix: in a new prompt/trial, show `{"op":"help","topic":"examples","syntaxVersion":2}` (and likewise for `define`/`replacement`) or say generically that Flow/2 help requests need `syntaxVersion:2`. Keep the source task, seed, runtime, and oracle fixed for that replay. This exposes the runtime's own discoverable documentation while preserving the current version-1 default for bare help and for unversioned authoring; silently changing those semantic defaults would confound compatibility and the experiment. A product follow-up could make bare help's index point explicitly to versioned help requests, but the prompt selector is the minimal controlled correction here.
