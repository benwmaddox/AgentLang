# 203 — Efficacy decision after organic vocabulary creation

Status: evidence checkpoint on 2026-10-11. No new participant was run for this
report. Historical experiments retain their original scores and runtime pins.

Continue the compact typed language and native arena work, but do not describe
the central accumulation hypothesis as validated. External coding agents have
discovered and composed supplied vocabulary, maintained typed application data,
and published tested functions. The completed comparisons have not established
more reliable edits than conventional F#. The first organic creation pilot
produced a correct implementation without the new shared abstraction needed to
test later-agent reuse.

The [previous decision](199-efficacy-decision-after-reference-maintenance.md)
separates behavior, evidence preservation and library qualification in the
six-participant maintenance cohort. Its original representation/setup failure
and separately labelled passing adapter result remain distinct. Inherited
examples were materially changed by one retained participant despite passing
library publication. The new pilot does not erase these findings or create a
larger pooled comparison.

The [organic pilot](200-organic-vocabulary-reuse.md) is one creator followed by
a conditional fresh successor, with a frozen stop rule. The creator's two
fixed-term renewal functions pass all 66 independent observations, 145 tests,
examples for 39 owners, library qualification and inherited-evidence
preservation. Both compose existing subscription functions. Their bodies
duplicate the cancellation/start structure with different term strings and
introduce no eligible shared helper. The archived score records an empty
eligible-helper set and `creatorReadyForSuccessor: false`.

| Research endpoint | Current evidence |
| --- | --- |
| Discover and compose existing typed vocabulary | Demonstrated on bounded tasks; the organic creator is another successful instance. |
| Make more reliable edits than F# | Not established by the completed small comparisons. |
| Naturally create a reusable shared abstraction | No eligible helper in this one organic creator; no general failure rate can be estimated. |
| Fresh successor discovers and uses that abstraction | Not observed in this pilot: no successor was dispatched. |
| Passing coverage establishes intended behavior or preservation | Contradicted as a sufficient criterion by earlier calibrated wrong solutions and changed inherited examples. Independent acceptance remains necessary. |
| Lower marginal cost, smaller context, or native service advantage | Not established by broker exchanges or these application trials. |

The creator's negative helper endpoint is informative even though its task
succeeds. It supports the distinction between reusing vocabulary supplied by
the environment and creating vocabulary that benefits a future developer.
One run cannot identify why duplication was chosen. Syntax, strict library
qualification, discovery cost and task size remain possible explanations to
test, not observed causes. No successor means missing downstream evidence,
not an observed downstream failure.

Do not manufacture a helper or change eligibility under trial 200. If research
resumes, use a separately named, predeclared study with the existing broker:
first test another unprompted creator opportunity; keep helper creation as its
own endpoint and dispatch a held-out successor only when that endpoint permits
it. A prompted factoring study could measure usability of creating a library
abstraction, but must not be labelled natural abstraction creation. A later
matched reuse comparison would still be required to estimate a benefit.

For now, resume native semantic conformance and the planned arena/mailbox
workloads rather than build more harness infrastructure. Strong types,
exhaustive matches, explicit effects, test-scoped replacements and strict
library coverage remain useful checked structure. Preserve independent
full-result/error expectations and collateral checks around them. Native
acceptance is engineering evidence; request/response throughput, memory and
tail latency require their own workloads and F# baseline.
