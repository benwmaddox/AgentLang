# 219 — Efficacy after typed batch maintenance

Decision on 2026-10-11: continue the compact typed language and native arena
track. Discoverable vocabulary is usable across fresh-agent handoffs, including
a changed persisted result contract. More reliable edits than conventional F#
remain unproven. This checkpoint adds no participant outcome and pools no studies.

The strongest recent result is a correct maintained abstraction, not lower cost.
In [217](217-typed-batch-failure-maintenance.md), both fresh agents changed the
existing batch result to a nominal failure record carrying the first failing
input's index, subscription ID and exact cause. Each passes all nine independent
full-result cases and independent preservation review. The retained candidate
also passes all 66 creator regressions and continues using the earlier renewal
functions. This extends the successful discovery/composition mechanism in
[215](215-efficacy-after-paired-vocabulary-pilot.md) to typed library maintenance.

Separate source correctness from completion. Retained passes 152 tests and reset
150, with all 137 common tests and 39 example owners passing in each. Retained's
overall endpoint passes with assistance; reset's fails after Ctrl+C, with no
host-close/session-end. Those are real transport outcomes. They do not establish
a language effect, and must not be erased by a later successful process reload.
The 39 versus 59 recorded exchanges describe these instances, with different
receipt completeness and unequal implementations. They are not model tokens,
effective context budgets, causal retention savings or comparative speed.

The [F# maintenance checkpoint](199-efficacy-decision-after-reference-maintenance.md)
still constrains the broad claim: conventional edits succeeded, F# used fewer
exchanges, and one retained language candidate materially changed inherited
examples. New correct language edits do not invalidate those observations.
Do not combine counts across changing tasks, seeds, runtime revisions or
representation adapters into a pooled reliability percentage.

Keep the features that make changes inspectable: nominal/refined types,
exhaustive matching, explicit effects, scoped dependency replacement, strict
library qualification and atomic definition publication. Their engineering
value is visible; their causal contribution to agent reliability is not isolated.
The [218 help correction](218-atomic-record-publication-help.md) explains complete
record CAS metadata and same-session publication. Its 44 passing local test
groups validate that engineering change, not improved agent behavior. Historical
217 outcomes belong to their frozen earlier runtime.

## Next measurement

The next agent measurement should compare fresh retained AgentLang and conventional
F# on failure-localization maintenance, rather than another easy language composition
task. Reuse the existing conventional broker, pure subscription domain and the nine
full-result cases. Establish and freeze an unmigrated batch seed before dispatch;
Give F# equivalent documented/tested renewal helpers, inherited scenarios and
public behavior so helper availability is not an unintended treatment difference.
The participant must change an existing result contract and preserve its inherited
scenarios, not implement an empty stub. Make nominal ID, exact first-error cause,
complete Store/list order and no input mutation equally explicit. Independently
review permitted test adaptations, then score an isolated copy with the same
semantic model. Keep participant-authored tests separate from the grader.

Calibrate the F# adapter with correct and incorrect localization outcomes before
dispatch. Supply the exact operation allowlist and `{"op":"host.close"}` transport
control up front to both conditions. Explain same-session record staging/publication
in the language bootstrap. Pin the new runtime and equivalent unmigrated seeds,
use fresh Luna/max contexts, recorded randomized order and matched budgets.
Do not retrofit those disclosures into 217 or treat a new arm as matched to the
old trials. A single fresh pair can expose another failure mode; it cannot
estimate a reliability ranking. No new harness framework, model-provider
integration or expansion of language capabilities is required.

Reuse `scripts/Start-SubagentTrialHostV2.ps1` and
`scripts/Audit-SubagentTrialTerminationV2.ps1`, the existing
`experiments/AgentLang.Conventional.Cli` project and the frozen semantic model in
`experiments/AgentLang.SubagentTrials/typed-batch-failure-216/oracle/model.py`.
The conventional seed/adapter is the necessary new work. Language-specific
identity/publication checks do not apply blindly to F#; local validation and
source preservation remain separate endpoints in each condition.

Native work need not wait for proof of superiority. Keep it separate: the next
useful [214 follow-up](214-completion-service-diagnostic.md) is a longer bounded
measurement at the earlier workload, with sustainable throughput, tail latency,
rejections and whole-process memory considered together. Retain both arena
policies until that evidence supports a choice; do not infer production readiness
from the interpreter or short overload diagnostic.
