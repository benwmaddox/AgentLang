# Milestone 005: bounded discovery and typed IR foundation

Status: published and validated implementation slice. Authoritative IR execution and the full PRD remain in progress.

This slice delivers deterministic structural search, transitive graph traversal, compact bounded context, and a typed semantic IR model/verifier. The current runtime still executes the checked AST; LLVM JIT/AOT remain conditional follow-ons.

The pure Discovery module and its test project are wired into Core, the solution and validation runner. Coordinating Release validation passed **53 discovery assertions**. Checks cover nominal distinctions, nested types, declared effects, static callback/refinement validator edges, unknown references, diamonds/cycles, bounded graph/context output, deterministic JSON, exact transported Unicode byte accounting and concise documentation.

The runtime protocol and human CLI expose nine commands: `type-of`, `search-type`, `search-output`, `search-effect`, `search-dependency`, `transitive-dependencies`, `transitive-callers`, `graph`, and `context`. Acceptance verifies current candidate/replacement visibility, exact nominal queries, structured query/budget errors, deterministic output, and bounded context without a dictionary dump. Queries do not execute words or mutate providers/vocabulary; active tasks record inspections. The [command contract](../docs/DISCOVERY.md) specifies defaults, hard limits and complete-entry omissions. The context byte budget covers the literal compact JSON `data` payload, including its own count and omission metadata; the fixed response envelope is separate. Bytes are never presented as model token usage.

The IR model/verifier is wired into Core and the validation runner, but remains separate from shared execution. An independent focused run passed **8 groups / 37 assertions** against the actual Core project. Executable types are closed; nominal keys belong to an immutable program snapshot; call sites carry concrete signatures and linked identities/revisions; effects use a closed ten-case union. The verifier checks generated operations, callback signatures/effects, branch joins, case-local scope, source ownership, coverage obligations and recursive call graphs. Qualified operation cases and distinct record labels avoid collisions with the source AST. These constructed-program checks establish the foundation, not compiler or interpreter parity.

Publication review found that the context builder's Unicode serialization settings differed from the JSON-lines transport. An independent serialization probe measured **85 versus 95 bytes** for the same JSON containing accented text, Japanese text, a generic type signature and an emoji. The builder now uses the protocol's default compact serializer. Passing regressions extract the literal `data` JSON from the serialized response and measure that transported representation, including Unicode documentation and a tight context budget. The independent review found no additional concrete defect in its scoped discovery/argument/visibility/logging audit.
