# 211 — Later developer reuse of creator-authored public vocabulary

Status: preflight accepted on 2026-10-11; developer dispatch is next. No developer
outcome is claimed yet.

This separately named study asks whether a fresh developer discovers and uses
the two public renewal functions created in trial 210 while implementing the
already specified held-out batch operation. Their names and signatures were
task-prescribed; this is public-vocabulary reuse, not spontaneous shared-helper
creation. Trial 210 remains closed with its original no-helper endpoint and no
successor. This study does not alter or resume its conditional chain.

The accepted creator snapshot is extracted from 210's sealed participant archive,
with every selected member checked against its hash index. Its project fingerprint
is `390c0ebc697b735a21e5f12efe508b5e192f3d04c1a8947d9174f1835f62edd2`.
The predeclared reuse targets are `subscription.renew-monthly` and
`subscription.renew-annual`. The developer receives a fresh copy of the project
and the original held-out task packet, without target names, previous results,
creator conversation or solution hints.

Correctness, inherited evidence preservation, library publication, returned-name
discovery, explicit inspection and production dependency paths are separate
endpoints. A correct implementation that does not call either target is accepted
behavior with a negative reuse result. Passing library coverage cannot substitute
for independent full-result/error checks.

The [frozen plan](../experiments/AgentLang.SubagentTrials/public-vocabulary-reuse-211/PLAN.md)
requires both targets to be discovered and reached from the production batch root
for its complete reuse endpoint. Per-target discovery and paths are also recorded,
so partial reuse remains visible. The thin scoring adapter delegates behavior,
preservation and call-graph checks to the reviewed 210 scorer; its internal helper
field names are compatibility data, not an optional-helper provenance claim.

Preparation reuses the exact freshly validated 210 CLI: all 37 relevant source
hashes and five runtime hashes still match. The prior 37-check V2 host verification
and six-control calibration remain tied to that binary. New held-out controls run
against the accepted creator project without redefining its renewal functions:
the correct batch matches 9/9 cases; partial-success and reverse-order mutants
match 4/9 and 6/9 and fail their intended cases. All 27 observations execute, with
145/145 inherited tests passing in each control process. This is control evidence,
not a participant outcome or library qualification for the controls themselves.

Adapter unit checks pass for target binding, exact-name discovery, exclusion of
test-only calls, missing production paths and rejection of nonzero scorer exits.
Real-snapshot binding verifies target identity/source/signature/maturity/tests and
an identical initial developer copy without executing the runtime. A preparer's
initial Python-only check reported a system-Temp cleanup permission failure;
the receipt is labelled self-reported and retained. Workspace-local fixtures and
the final root checks pass. No runtime executed in that failed check attempt.

[Pre-dispatch evidence](evidence/211-public-vocabulary-reuse/preflight.zip) and
[index](evidence/211-public-vocabulary-reuse/preflight.index.json) retain 1,453
members: study inputs, adapter, imported oracle sources, accepted and initial
project snapshots, target binding, control receipts and runtime/source pins.
Every archive member was reopened and its length and SHA256 verified before
dispatch. Participant output will be kept separately.

Use one fresh Luna/max participant, its assigned broker, a 100-exchange limit,
virtual I/O and empty external capabilities. External-tool isolation remains
prompt-governed; the broker is not an OS sandbox. No new external capability,
public listener or language escape hatch is introduced.

One accepted reuse instance would demonstrate this chain's feasibility. It would
not show that retention causes better reliability, fewer tokens or lower marginal
development cost. A matched reset comparison would still be needed to estimate
benefit, and service performance remains a separate research track.
