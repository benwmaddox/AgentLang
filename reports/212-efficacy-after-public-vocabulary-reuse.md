# 212 — Efficacy after later-agent public vocabulary reuse

Status: evidence checkpoint on 2026-10-11. No new participant run, language change
or native performance measurement is claimed in this report.

Continue the compact typed language. A later fresh developer has now discovered
and correctly reused public library functions built by a previous developer.
That is evidence for the intended handoff mechanism. It still does not establish
more reliable edits than F#, a benefit caused by retaining vocabulary, or lower
memory and higher throughput. These questions require separate comparisons.

The [previous checkpoint](203-efficacy-decision-after-organic-creation.md)
recorded a correct creator without an optional shared helper. A
[fresh replication](210-organic-reuse-replication.md) also passes all 66 independent
observations, 145 tests and 39 example owners, with inherited evidence preserved.
It creates the requested monthly and annual renewal functions, but no eligible
optional helper. Both original studies retain their no-successor stop rules.
Two outcomes on the same task opportunity cannot estimate a general abstraction
creation rate or explain the choice to duplicate the lookup/cancel/start structure.

The helper criterion was narrower than the product hypothesis. Requested public
functions are also persistent project understanding. The separately frozen
[public-vocabulary study](211-public-vocabulary-reuse.md) gives a fresh developer
the accepted creator project and held-out batch task, without target names or
previous results. It discovers both renewal functions through search, reads their
source and reaches both through its production batch helper. Independent scoring
passes 66 original and nine held-out observations, 152 tests and all 39 example
owners. Target identities, source, signatures, library maturity and own tests
remain intact. The broker closes normally after 28 exchanges.

| Research question | Evidence and limit |
| --- | --- |
| Can a fresh agent find and compose typed vocabulary? | Yes on bounded tasks, now including public functions authored by an earlier agent. |
| Can one agent leave useful vocabulary for another? | One successful held-out public-function handoff. Names and signatures were task-prescribed; usefulness is demonstrated as production reuse, not a measured outcome advantage. |
| Do agents naturally factor shared abstractions? | Neither of two creator opportunities produces the qualifying optional helper. This is a negative endpoint for those opportunities, not proof that agents cannot factor. |
| Does retention improve reliable edits? | Unproven. Trial 211 has no reset arm. Earlier small maintenance comparisons do not establish superiority over conventional F#. |
| Does library coverage ensure intended behavior? | No. It checks exercised paths and finite cases; independent behavior and inherited-evidence checks remain necessary. Earlier changed examples and calibrated wrong solutions still matter. |
| Are tokens, context or native service performance improved? | Unproven. Broker exchanges are not provider tokens; application trials are not native throughput benchmarks. |

Preserve strong nominal/refined types, exhaustive matching, explicit effects,
test-scoped replacements and strict library qualification. The observed handoff
uses this structure successfully. Keep behavior, publication, collateral
preservation, discovery and actual production reuse as separate acceptance
criteria. Source inspection is allowed and useful; relying on it here does not
demonstrate operation without source or with smaller context windows.

The next minimal efficacy experiment is a fresh retained/reset pair on the same
batch task, using the existing broker and nine-case model. Retained starts with
the accepted creator functions; reset starts with the preceding domain seed.
Both receive the same task, runtime, model, budget, interface and effect policy.
Do not reuse trial 211 as a concurrently frozen retained arm. Preserve each arm's
own inherited evidence, require the batch library gate, and score the same full
results and error precedence. Report this as a small vocabulary-availability
pilot, not primitives-only versus growing vocabulary or a population estimate.
Different inherited suites and one participant per arm remain limitations.

Use a condition-neutral behavior scorer: reset must not fail merely because the
retained targets do not exist. Discovery and retained production paths are
secondary observations, not requirements for reset correctness. Calibrate
correct, wrong-order and partial-success controls in both seed conditions before
dispatch. Add no new harness framework, host capability or public listener.
Trials use virtual I/O and empty external grants; external-tool isolation remains
prompt-governed rather than an OS sandbox.

Native LLVM semantic conformance and arena/mailbox work remain the secondary
track. No allocation policy, backend or service-performance decision follows
from this report. The product remains external coding agents editing an
inspectable language, not AI agents embedded in language internals.
