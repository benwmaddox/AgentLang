# 215 — Efficacy after the paired vocabulary pilot

Status: evidence decision on 2026-10-11. Continue the compact typed language,
but the primary claim of more reliable edits remains unproven. This checkpoint
adds no participant outcome and does not pool incompatible experiments.

The latest evidence supports a narrower, useful mechanism: a fresh external
coding agent can find library functions created by an earlier agent, understand
their behavior and compose them correctly. In the fresh matched task pilot,
both reset and retained projects produce correct edits; retained uses fewer
broker exchanges. This does not yet establish superior reliability, causal
traffic savings, smaller contexts or general marginal development cost.

| Question | Current evidence | What remains open |
| --- | --- | --- |
| Does discoverable vocabulary survive a handoff? | 211 discovers and reuses both earlier renewal functions; fresh retained 213 independently does so again. | Only one creator task family; names/types were prescribed. |
| Does availability change correct outcomes? | 213 reset and retained both pass nine independent cases and preserve inherited evidence. | No per-instance correctness difference; one pair cannot estimate reliability. |
| Does availability reduce interaction burden? | 213 retained uses 31 exchanges versus reset's 39. | Different agents and sequential order; traffic is not model tokens or causal feature attribution. |
| Do agents spontaneously factor reusable helpers? | Neither 200 nor 210 creates the qualifying optional helper; their requested public functions are still useful vocabulary. | Do not erase the frozen negative endpoint or infer a general creation rate. |
| Does the approach beat F# on reliable maintenance? | 179 has six successful repair/migration sequences; 196 has successful F# edits and a retained preservation issue. | No established superiority; F# uses fewer exchanges in those studies. |
| Do library tests establish correct intent and collateral preservation? | Strong types, coverage and qualification are exercised successfully, but wrong expected values can pass coverage and one inherited scenario was replaced. | Independent behavior and source/evidence preservation are still needed. |
| Is the native runtime competitive? | 214 passes bounded diagnostic correctness and cleanup. | All overload groups fail rejection qualification; no general throughput or policy winner. |

The [paired pilot](213-paired-vocabulary-availability.md) uses two fresh contexts,
identical task/runtime/broker budgets, separate initial projects and a neutral
nine-case full-result model. All 137 common tests and 39 example owners pass in
both; total tests are 148 and 151. Retained reaches both renewal functions in
its production graph; reset composes the domain seed directly. A lifecycle-only
reset intervention and unequal inherited suites remain documented limitations.
It is domain-rich reset, not the PRD primitives-only flat mode, and has no F# arm.

Earlier evidence continues to constrain interpretation. The
[repair/migration sequence](179-preview-repair-and-record-migration.md) and
[typed-reference cohort](196-typed-reference-maintenance-cohort-results.md) test
harder edits, with different seeds and protocols. The original scalar-only
checker incompatibility and [record supplement](197-typed-reference-record-supplement.md)
remain separate. Passing a supplemented checker does not retroactively change
the frozen original score. Material example changes do not become preservation
merely because IDs survive or assertions become stronger.

Keep strong nominal/refined types, exhaustive matching, explicit effects,
test-scoped replacement and library coverage. The current evidence supports
usable checked structure and inspectable changes, not a proof that these features
cause better agent outcomes. Definition-level edits and atomic publication expose
meaningful boundaries; source inspection remains useful and allowed.

The next minimum useful step is [typed failure-localization maintenance](../experiments/AgentLang.SubagentTrials/typed-batch-failure-216/PLAN.md):
change the existing batch's error to a record carrying the first failing input
index, nominal subscription ID and exact cause. Reuse the nine independent cases
and existing brokers, with explicit allowed test adaptations and an independent
preservation review. This extends beyond append-only composition into a changed
persisted result contract and fold state. Both accepted terminal 213 projects
are starting inputs, so it is a paired continuation probe with unequal authored
implementations, not a clean retention ablation. No participant has been run.
Preflight must demonstrate the migration and discriminate wrong localization
before freezing. A conventional counterpart and repeated harder tasks are still
needed before a comparative reliability claim.

Native LLVM/interpreter semantics and arena allocation remain a separate second
track. [214](214-completion-service-diagnostic.md) leaves completion draining
opt-in, both arena policies available and the old default intact. Its short
64,000/s overload does not explain the earlier 500/s qualification failure.
No provider token/context measurements are available in these broker studies.
No new external capability, public listener or arbitrary .NET invocation is
introduced by this research. Trials use virtual I/O and empty effect grants;
prompt-governed participant isolation is not an OS sandbox.

The [input index](evidence/215-efficacy-after-paired-vocabulary-pilot/index.json)
pins the reports and sealed evidence used here. This is a continuation decision,
not completion of the PRD or validation of every product hypothesis.
