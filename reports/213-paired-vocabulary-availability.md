# 213 — Fresh retained/reset vocabulary availability pilot

Status: preflight accepted on 2026-10-11. Neither participant has been dispatched;
no participant outcome or comparative benefit is claimed.

The [efficacy checkpoint](212-efficacy-after-public-vocabulary-reuse.md) separates
the demonstrated public-function handoff from unproven retention benefit. This
study prepares one new fresh developer per condition on the same held-out batch
task. The retained baseline contains the accepted 210 creator's two renewal
functions; reset contains the preceding domain seed. Both use Luna/max, the
accepted CLI, identical broker permissions and a 100-exchange limit. The
recorded pre-dispatch random order is reset, then retained. Trial 211 remains
historical evidence and supplies neither matched participant.

The [frozen protocol](../experiments/AgentLang.SubagentTrials/paired-vocabulary-213/PLAN.md)
and [shared task packet](../experiments/AgentLang.SubagentTrials/paired-vocabulary-213/preparation/task-packet.md)
keep correctness independent of reuse. Each candidate must pass the same nine
full-result/error cases, publish the batch with its own tests and preserve both
the common seed and its own arm's inherited evidence. Discovery and production
paths to the retained functions are secondary observations. Reset may author
new supporting functions and is not required to refer to retained targets.

The adapter imports the previous model/projection routines directly; it does
not invoke the optional-helper successor gate or fabricate helper eligibility.
All scoring executes on copies. Test/example counts for the common seed remain
separate from condition-specific and newly authored evidence. One pair cannot
estimate a population reliability advantage. This is domain-rich reset, not
the primitives-only flat condition, and has no conventional arm.

Preparation verifies 37 unchanged source inputs and five runtime files against
the accepted fresh 210 build. Both initial actor copies match their baseline.
The first control attempt stops during its last retained fixture copy at the
Windows path-length limit. Its receipts and partial files remain separate from
the fresh retry using shorter evidence paths. This is observer preparation,
not a language behavior or participant failure. The fresh retry passes all six
controls: correct 9/9, partial-success 4/9 and reverse-order 6/9 in each condition,
with all 54 observations executing and inherited suites/examples passing.

The new adapter passes 11 fixture checks and independent read-only review.
Executable calibration against the known-correct sealed 211 project passes all
nine cases under both baseline policies, with 152 total tests, 137 common-seed
tests and 39 example owners. This is a scorer fixture, not either new participant.
The fixture and both new actor copies remain unchanged. Review identified an
ambiguous parameter-name instruction; the shared packet now explicitly permits
local parameter names to differ while fixing declared types, fields, cases and
function names. No outcome is used to adjust the task or its nine-case model.

[Pre-dispatch evidence](evidence/213-paired-vocabulary-availability/preflight.zip)
and [index](evidence/213-paired-vocabulary-availability/preflight.index.json)
retain the protocol, shared packet, reviewed adapter/imported oracle sources,
initial projects, source/runtime pins and closed control/calibration receipts.
Saved control/scoring project copies are omitted from this package; exact
baseline snapshots, requests, responses and receipt hashes are retained.
Participant output will be archived separately.

No new capability, public listener or language escape hatch is added. Runtime
and broker work uses virtual I/O and empty external effect grants. External-tool
isolation is prompt-governed; the broker is not an OS sandbox. No provider-token,
context-size, native throughput or arena-policy result follows from this pilot.
